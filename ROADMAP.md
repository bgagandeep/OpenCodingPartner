# Roadmap

OpenCodingPartner is a chat agent plus an orchestration agent swarm. The swarm stands up multiple agents: coding, QA, security, and computer. That is the product, including now.

## Now

The offline core runs without the orchestration gateway, the coding worker, or System-1 installed. `ocp doctor` tells a new operator which of those pieces are present. `ocp prove coding` runs one scripted coding turn with no API key: mkdir, write, glob, patch, copy the patched file, and `node --test`. The copy stays local. `ocp prove computer` runs one scripted computer chain with a fake browser driver: open, scroll, press Enter, hover a selector, double-click a selector, right-click a selector, fill a selector, select an option by label, check or uncheck a box, and check page text. That is not a full go-to-market run. The orchestration gateway does not run the browser. The offline demo still does not pretend they are live. This is not a Board showtime. It is not a finished coding product. `PARTNER.md` is the partner agreement. An open edit in a sandbox that has that file shows an Approve card and waits for `approve` or `accept the plan`, then runs `node --test` and reports the exit code. `deny` and `redirect:` decide that card. A failed check returns to intent and holds the coding worker at one. `PARTNER.rules` and `.ocp/rules` load into the coding worker. `ocp computer` is the Computer tab: sandbox status, last frame, takeover, and return. After computer-execute, capture writes the step screenshot to `gtm/last-frame.png` and Computer QA `computer-frame` checks it. A missing page or a bad frame fails the turn in the transcript. With a partner id, the frame stays in `.ocp/fleet/<id>/gtm/`. `ocp computer qa` prints pass or fail and does not open a page. `ocp doctor` reports Computer capture readiness and does not start the browser. A live stream is later. Computer-use waits on an Approve card when `PARTNER.md` is present. A partner id uses its own workspace under `.ocp/fleet/<id>`, with a read-only shared mount. `ocp fleet start` and `ocp fleet stop` run Docker when it is installed, and fail clearly when it is not. Later: a fleet grid and telemetry. Not in this build. Routines can wait on an interval or an event name and then run a partner turn. Slack and Telegram text uses that turn, including approve and deny. Slack posts a reply when `SLACK_BOT_TOKEN` and `SLACK_SIGNING_SECRET` are set. Inbound Slack events are checked with that signing secret. Without them the offline turn still runs. Telegram posts a reply when `TELEGRAM_BOT_TOKEN` and `TELEGRAM_WEBHOOK_SECRET` are set. Inbound Telegram updates are checked with that webhook secret. Without them the offline turn still runs. WhatsApp and telemetry are later. `docs/examples/swarm.json` is a swarm manifest. `ocp swarm apply` creates the partner workspaces and routines. `--dry-run` writes nothing. Live container start and a fleet grid are later. Advanced ACP is off unless `OCP_ACP=1` or Settings `advanced.acp` is true. The name of that optional backend is in Credits. It is not installed. Packaging is a free OSS core. Seats and credits in Settings are design only. Billing is inert. No payment provider is connected.

- Chat agent CLI: `ocp` and `opencodingpartner`.
- Orchestration agent swarm with a session key like `agent:board:main`.
- Coding agent and QA agent on the coding worker, or on the operator's meter proxy, with a local sandbox for real file writes and a QA check.
- Security agent gate before writes.
- Computer agent seam. It records a plan with `executed: false` until you pass `--computer-execute` and name a URL. Then Playwright opens that URL, reads the screen, and types into one selector when the message asks.
- System-1 uses the installed route model through `integrations/laya/predict.py`. `pnpm bundle:install` downloads the English weights into `.bundle/laya/hf`. The transcript says real or fallback.

A temporary early-test cap of 8 agents is in the code. It is temporary. The demo stands up four agents in one turn.

Ads are off. Payments are off in the core.

## Next

`pnpm bundle:install` already installs the pinned orchestration gateway, coding worker, and System-1 beside this repo. `ocp demo --live` checks that they answer.

- The orchestration gateway can drive sandbox writes. After it accepts the session plan, it invokes the local write bridge (`ocp_sandbox_write`). The transcript says orchestration. When the gateway is down, the same create-file is a local sandbox write. `fs_write` and `sessions_spawn` stay blocked.
- Start the orchestration gateway with `docker compose up -d openclaw-gateway` and send session traffic through it. Load `integrations/openclaw-sandbox-write` so the gateway can call the bridge.
- Send a real coding prompt through the coding worker when the operator has a key.
- A later chat turn on the same sandbox sees the text files already there and a short `Prior turns:` history for that session and sandbox. The meter prompt includes those files and skips secrets. History does not keep blocked secrets. It is stored in `.ocp/prior-turns.json` in that sandbox so it survives a restart. One coding turn can list, grep, glob a relative pattern such as `src/**/*.ts`, read, patch, write, delete one file, rename one file, copy one file (through `ocp_sandbox_copy` when the gateway drove the turn, otherwise locally; a missing plugin falls back locally; a refusal does not copy locally). Append adds text to one existing relative file and does not create a file (through `ocp_sandbox_append` when the gateway drove the turn, otherwise locally; a missing plugin falls back locally; a refusal does not append locally). A missing file, a directory, `../`, a secret, `gtm/`, or `.ocp/` is refused. The transcript says `Append path: orchestration.` or `Append path: local sandbox.` The turn can also mkdir one directory and run `node --test`, `pnpm test`, or `tsc --noEmit`, plus read-only `git status` and `git diff` with relative paths, and `git log --oneline -n N` with N from 1 to 20, and `git show HEAD:` plus one relative path, then take more rounds from those results (up to ten). When the gateway drove the turn, delete, rename, mkdir, rmdir, and copy use `ocp_sandbox_delete`, `ocp_sandbox_rename`, `ocp_sandbox_mkdir`, `ocp_sandbox_rmdir`, and `ocp_sandbox_copy`. The transcript says orchestration. A missing plugin falls back to the local sandbox. Rename refuses an existing target, `gtm/`, and a secret source. When the gateway drove the turn, mkdir uses `ocp_sandbox_mkdir`. The transcript says orchestration. A missing plugin falls back to the local sandbox. When the gateway drove the turn, rmdir uses `ocp_sandbox_rmdir`. The transcript says orchestration. A missing plugin falls back to the local sandbox. A refusal does not remove the directory locally. The coding agent can add and complete todos in that turn. The list is local, capped at 12, and stored in `.ocp/todos.json`. Secrets and `../` are refused. The orchestration gateway does not keep the list. A file or a non-empty directory is refused. An existing directory is a no-op. A file, `../`, `gtm/`, `.ocp/`, or a secret path is refused. Grep returns path and line snippets so the model can edit the hit file without reading the whole tree. A failed check is still retried up to two times.
- The computer agent can run a short chain: open, read, type, click, navigate on the same host, wait for a selector, scroll the page or a selector into view, press Enter, Escape, Tab, Backspace, or an arrow key. Any other key fails. It can hover a selector or quoted text. It can double-click a selector or quoted text. It can right-click a selector or quoted text. It can fill a selector or quoted field with quoted text, which clears the field first. It can select an option by its visible label on a selector or quoted field. It can check or uncheck a selector or quoted label. A missing selector, quoted target, or option fails that step. It can check a title, page text, or selector value. A wait longer than 30 seconds fails. A scroll larger than 2000 pixels fails. The orchestration gateway does not run the browser. A failed step is recorded in `gtm/last-run.json` and later steps stay unexecuted. The QA agent fails a coding write when expected file text is missing, a file is empty, or security removed it. A failed file or page check is retried up to two times on the same write path, then the transcript says the budget is exhausted. Longer browser sessions can come later.
- Keep System-1 on route and policy only. Weights stay on the operator machine.

## Later
