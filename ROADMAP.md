# Roadmap

OpenCodingPartner is a chat agent plus an orchestration agent swarm. The swarm stands up multiple agents: coding, QA, security, and computer. That is the product, including now.

## Now

Packaging is a free OSS core. Seats and credits in Settings are design only. Billing is inert. No payment provider is connected.

- Chat agent CLI: `ocp` and `opencodingpartner`.
- Orchestration agent swarm with a session key like `agent:board:main`.
- Coding agent and QA agent on the coding worker, or on the operator's meter proxy, with a local sandbox for real file writes and a QA check.
- Security agent gate before writes.
- Computer agent seam. It records a plan with `executed: false` until you pass `--computer-execute` and name a URL. Then Playwright opens that URL, reads the screen, and types into one selector when the message asks.
- System-1 uses the installed route model through `integrations/laya/predict.py`. `pnpm bundle:install` downloads the English weights into `.bundle/laya/hf`. The transcript says real or fallback.

A temporary early-test cap of 8 agents is in the code. It is temporary. The demo stands up four agents in one turn.

Ads are off. Payments are off in the core.

## Next

`pnpm bundle:install` already installs the pinned orchestration gateway, coding worker, and System-1 beside this repo. `ocp demo --live` checks that they answer.

- The orchestration gateway can drive sandbox writes. After it accepts the session plan, it invokes the local write bridge (`ocp_sandbox_write`). The transcript says orchestration. When the gateway is down, the same create-file is a local sandbox write. `fs_write` and `sessions_spawn` stay blocked.
- Start the orchestration gateway with `docker compose up -d openclaw-gateway` and send session traffic through it. Load `integrations/openclaw-sandbox-write` so the gateway can call the bridge.
- Send a real coding prompt through the coding worker when the operator has a key.
- A later chat turn on the same sandbox sees the text files already there and a short `Prior turns:` history for that session and sandbox. The meter prompt includes those files and skips secrets. History does not keep blocked secrets. It is stored in `.ocp/prior-turns.json` in that sandbox so it survives a restart. One coding turn can list, grep, glob a relative pattern such as `src/**/*.ts`, read, patch, write, delete one file, rename one file, copy one file (through `ocp_sandbox_copy` when the gateway drove the turn, otherwise locally; a missing plugin falls back locally; a refusal does not copy locally). Append adds text to one existing relative file and does not create a file (through `ocp_sandbox_append` when the gateway drove the turn, otherwise locally; a missing plugin falls back locally; a refusal does not append locally). A missing file, a directory, `../`, a secret, `gtm/`, or `.ocp/` is refused. The transcript says `Append path: orchestration.` or `Append path: local sandbox.` The turn can also mkdir one directory and run `node --test`, `pnpm test`, or `tsc --noEmit`, plus read-only `git status` and `git diff` with relative paths, and `git log --oneline -n N` with N from 1 to 20, and `git show HEAD:` plus one relative path, then take more rounds from those results (up to ten). When the gateway drove the turn, delete, rename, mkdir, rmdir, and copy use `ocp_sandbox_delete`, `ocp_sandbox_rename`, `ocp_sandbox_mkdir`, `ocp_sandbox_rmdir`, and `ocp_sandbox_copy`. The transcript says orchestration. A missing plugin falls back to the local sandbox. Rename refuses an existing target, `gtm/`, and a secret source. When the gateway drove the turn, mkdir uses `ocp_sandbox_mkdir`. The transcript says orchestration. A missing plugin falls back to the local sandbox. When the gateway drove the turn, rmdir uses `ocp_sandbox_rmdir`. The transcript says orchestration. A missing plugin falls back to the local sandbox. A refusal does not remove the directory locally. It does not run a turn. `ocp copy --from --to` copies one file in this workspace and leaves the source. It does not overwrite. A directory stays. A secret file stays. - The computer agent can run a short chain: open, read, type, click, navigate on the same host, wait for a selector, scroll the page or a selector into view, press Enter, Escape, Tab, Backspace, or an arrow key. Any other key fails. It can hover a selector or quoted text. It can double-click a selector or quoted text. It can right-click a selector or quoted text. It can fill a selector or quoted field with quoted text, which clears the field first. It can select an option by its visible label on a selector or quoted field. It can check or uncheck a selector or quoted label. A missing selector, quoted target, or option fails that step. It can check a title, page text, or selector value. A wait longer than 30 seconds fails. A scroll larger than 2000 pixels fails. The orchestration gateway does not run the browser. A failed step is recorded in `gtm/last-run.json` and later steps stay unexecuted. The QA agent fails a coding write when expected file text is missing, a file is empty, or security removed it. `ocp doctor` says whether the last QA passed and does not print the summary. A failed file or page check is retried up to two times on the same write path, then the transcript says the budget is exhausted. Longer browser sessions can come later.
- Keep System-1 on route and policy only. Weights stay on the operator machine.
